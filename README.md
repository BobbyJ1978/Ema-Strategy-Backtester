# بک‌تستر EMA/SMA — BTC Intraday V1

پیاده‌سازی کامل مشخصات «EMA/SMA BTC Intraday V1» با **Next.js 14 (App Router)** + **TypeScript** + **Tailwind CSS** + **Recharts** + **Vitest**.

استراتژی: کراس EMA4/EMA16 با فیلتر روند SMA64 روی **BTCUSDT پرپچوال (USDT-M)**، تایم‌فریم **15m**، منطقه زمانی **UTC**، جهت Long و Short، حداکثر یک پوزیشن باز، بدون نگهداری پوزیشن تا روز بعد.

```powershell

```

```powershell

```

```powershell

```

```

## منبع داده

### Binance عمومی (پیش‌فرض)
داده کندل‌ها و نرخ فاندینگ از API عمومی Binance USDT-M Futures (`fapi.binance.com`) بدون API Key دریافت می‌شود.

اگر در منطقه شما `fapi.binance.com` مسدود است، فایل `.env.example` را به `.env` کپی کنید و آدرس جایگزین را در متغیر `BINANCE_FAPI_BASE` قرار دهید.

### فایل CSV
در فرم برنامه، منبع داده را روی «CSV» بگذارید و محتوای فایل OHLCV را در کادر متن وارد کنید.

قالب پذیرفته‌شده (جداکننده کاما یا نقطه‌ویرگول؛ نام ستون‌ها انعطاف‌پذیر است):
```
timestamp,open,high,low,close,volume
1704067200000,42000,42100,41950,42050,123.4
1704068100000,42050,42120,42000,42100,98.7
```
- `timestamp`: میلی‌ثانیه UTC (یا تاریخ قابل پارس UTC مانند `2024-01-01T00:00:00Z`)
- ستون‌های مجاز برای زمان: `timestamp`, `open_time`, `time`, `date`
- ستون‌های مجاز برای حجم: `volume`, `vol`

## قوانین استراتژی (V1)

- **سیگنال:** کراس صعودی EMA4/EMA16 = `ema4[t-1] <= ema16[t-1] && ema4[t] > ema16[t]` (نزولی برعکس). سیگنال فقط بعد از بسته‌شدن کامل کندل اعمال می‌شود.
- **فیلتر روند Long:** `close[t] > sma64[t] && sma64[t] > sma64[t-4] && ema16[t] > sma64[t]` (برای Short برعکس).
- **ورود:** مارکت در **Open کندل بعدی**؛ اگر کندل بعدی ساعت 00:00 UTC باز شود یا خارج از روز UTC سیگنال باشد، ورود ممنوع.
- **حد ضرر/سود:** `SL = 1.5 × ATR14(کندل سیگنال)`، `TP = 2 × SL`. SL ثابت است. برخورد همزمان SL و TP → SL اولویت دارد. گپ از روی SL → اجرا در Open (بدتر). TP محافظه‌کارانه → اجرا در خود TP.
- **اولویت خروج:** SL → TP → کراس مخالف EMA4/EMA16 (خروج در Open کندل بعدی) → بستن اجباری در Close آخرین کندل 15m روز (کندلی که به 00:00 UTC ختم می‌شود).
- **حجم پوزیشن:** `risk = equity × 0.5%`، `qty = risk / |entry − SL|` گرد‌شده به پایین تا گام مقدار؛ در صورت کمتر از حداقل، معامله رد می‌شود.
- **هزینه‌ها:** کارمزد ورود و خروج جداگانه (قابل تنظیم؛ نرخ دقیق صرافی نیست)، اسلیپیج بر حسب bps در جهت نامطلوب، فاندینگ تاریخی (Long نرخ مثبت می‌پردازد). در نبود داده فاندینگ، پرچم `funding_data_missing` فعال می‌شود.
- **Warmup:** حداقل ۲۰۰ کندل قبل از اولین کندل بک‌تست؛ اندیکاتورها در مرز روز ریست نمی‌شوند.
- **کیفیت داده:** خطاهای بحرانی اجرا را متوقف می‌کنند؛ گپ‌ها گزارش می‌شوند و با سیاست `exclude_segment` فقط بزرگ‌ترین قطعه پیوسته نگه داشته می‌شود؛ آخرین کندل ناقص حذف می‌شود.

    execution/            شبیه‌ساز (ورود، SL/TP، خروج‌ها، فاندینگ)
    risk/                 محاسبه حجم پوزیشن
    costs/                کارمزد، اسلیپیج، فاندینگ
    analytics/            متریک‌ها و خلاصه ماهانه
    storage/              خروجی CSV و ذخیره اجراها
tests/                    ۷ فایل تست (۳۴ تست) با Vitest
```

## نکات

- اجراها **قطعی (deterministic)** هستند؛ دو اجرای با ورودی یکسان خروجی یکسان می‌دهند.
- هیچ نشانه‌ای از **سوگیری آینده‌نگر (look-ahead bias)** وجود ندارد؛ تست مخصوص آن در `tests/test_no_lookahead.test.ts` نوشته شده است.
- زمان‌بندی همه‌جا UTC است و داده فاندینگ فقط تاریخی است.
